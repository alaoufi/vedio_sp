# البناء، مفتاح التوقيع، والتحديث دون فقدان البيانات

هذا الملف يشرح بوضوح: **مفتاح التوقيع**، وكيف يجعل أي بناء جديد **يُحدّث** التطبيق
المثبّت فيحفظ قاعدة البيانات (لا يمسحها)، ومفتاح تشفير القاعدة، ورقم النسخة.

اقرأه مع: `docs/DEVELOPER_GUIDE.md` و`docs/DATABASE.md`.

---

## 1. مفتاحان مختلفان — لا تخلط بينهما

| المفتاح | ما هو | أين | هل تتحكّم فيه؟ |
|--------|-------|-----|----------------|
| **مفتاح التوقيع** (signing key) | يوقّع ملف الـAPK؛ أندرويد يسمح بالتحديث فوق تطبيق مثبّت **فقط** إذا كان التوقيع بنفس المفتاح | `app/debug.keystore` (مُضمَّن في المستودع) | **نعم** — ثابت ومشترك |
| **مفتاح تشفير القاعدة** (DB passphrase) | يفكّ تشفير قاعدة SQLCipher | يُولَّد عشوائيًا على الجهاز ويُحفظ في Android Keystore | **لا** — تلقائي، لا يُكتب في الكود |

> العلاقة بينهما: مفتاح تشفير القاعدة يعيش داخل تخزين التطبيق المربوط بـ**هويّة
> التطبيق + توقيعه**. لذلك **الحفاظ على مفتاح التوقيع ثابتًا** هو ما يبقي القاعدة
> قابلة للفتح عبر التحديثات. تغيير المفتاح أو إلغاء التثبيت = فقدان البيانات.

---

## 2. مفتاح التوقيع (المُضمَّن)

الملف: **`app/debug.keystore`** — مُضمَّن عمدًا في المستودع (استثناء صريح في
`.gitignore`: `!debug.keystore`) ليكون كل بناء موقّعًا بنفس المفتاح.

بيانات الاعتماد (من `app/build.gradle.kts` → `signingConfigs`):

```
storeFile    = app/debug.keystore
storePassword = android
keyAlias      = androiddebugkey
keyPassword   = android
```

وإعداد نوع البناء debug:
```kotlin
debug {
    applicationIdSuffix = ".debug"                       // هوية ثابتة
    signingConfig = signingConfigs.getByName("debug")    // نفس المفتاح دائمًا
}
```

> هذا مفتاح **debug** قياسي (كلمة المرور `android`) — عملي لتطبيق شخصي يُوزَّع خارج
> المتجر. إن أردت نسخة release للمتجر، أنشئ keystore خاصًا واحفظه في مكان آمن (لا
> ترفعه)، لكن عندها **يجب أن تبقي عليه إلى الأبد** لتستمر التحديثات دون فقدان بيانات.

## 3. لماذا «التطوير عليه يُحدّث البيانات فقط»؟

عند إعادة البناء والتثبيت، تُحفظ بيانات المستخدم **بشرطين معًا**:

1. **نفس هوية التطبيق** — `applicationId = com.myvideolibrary.app` مع لاحقة
   `.debug` ثابتة. (لا تغيّرها بين الإصدارات.)
2. **نفس مفتاح التوقيع** — `app/debug.keystore` المُضمَّن. (لا تغيّره.)

عند تحقّقهما، تثبيت الـAPK الجديد = **تحديث في المكان (update-in-place)**: يبقى ملف
القاعدة المشفّر ومفتاح Keystore، وتُطبَّق **ترحيلات Room** على المخطّط. النتيجة:
البيانات تُحدَّث (تُرحَّل) ولا تُمسح.

### ما الذي يمسح البيانات؟ (تجنّبها)
- إلغاء تثبيت التطبيق ثم تثبيته (يمسح تخزينه ومفتاحه).
- تغيير `applicationId` أو مفتاح التوقيع → أندرويد يرفض التحديث ويطلب إلغاء تثبيت.
- تغيير المخطّط **دون** ترحيل مناسب مع `fallbackToDestructiveMigration` (لا تفعل).
  المشروع يستخدم `fallbackToDestructiveMigrationOnDowngrade()` فقط — أي التدمير
  يحدث **فقط عند التنزيل لإصدار أقدم**، لا عند الترقية.

## 4. تحديث المخطّط مع حفظ البيانات (خطوات ملزمة)

لأي تغيير في بنية الجداول:

1. عدّل الـ`@Entity` المعني في `data/local/entity/`.
2. زد رقم الإصدار في `AppDatabase`:
   `@Database(version = N)` → `N+1`.
3. أضف ترحيلًا في `data/local/Migrations.kt`:
   ```kotlin
   val MIGRATION_N_N1 = object : Migration(N, N + 1) {
       override fun migrate(db: SupportSQLiteDatabase) {
           db.execSQL("ALTER TABLE videos ADD COLUMN new_col TEXT")
       }
   }
   ```
4. سجّله في `di/DatabaseModule.addMigrations(...)`.
5. ابنِ ووقّع بنفس المفتاح → التحديث يُرحّل البيانات تلقائيًا.

> مخطّطات Room تُصدَّر إلى `app/schemas/` (مضبوط عبر
> `room.schemaLocation`) — احفظها في المستودع لمراجعة الفروق واختبار الترحيلات.

## 5. رقم النسخة (versionName / versionCode)

يُضبطان في `app/build.gradle.kts`:
```kotlin
versionCode = (project.findProperty("versionCode") as String?)?.toIntOrNull() ?: 1
versionName = (project.findProperty("versionName") as String?) ?: "1.0.0"
```

| السياق | versionCode | versionName |
|--------|-------------|-------------|
| بناء محلي بدون معاملات | `1` | `1.0.0` |
| بناء CI (GitHub Actions) | `github.run_number` | `1.0.<run_number>` |

- كل دفع على الفرع يبني نسخة برقم تشغيل أعلى، فتُحدّث سابقتها في المكان.
- **النسخة الحالية:** `1.0.<آخر رقم تشغيل ناجح>` — كانت **1.0.169** وتتزايد مع كل
  بناء لاحق. الرقم الدقيق للأحدث يظهر في صفحة الإصدار:
  `https://github.com/alaoufi/vedio_sp/releases/tag/apk-latest`.
- لبناء محلي برقم صريح:
  ```bash
  ./gradlew assembleDebug -PversionCode=170 -PversionName=1.0.170
  ```

> **قاعدة:** `versionCode` يجب أن **يتزايد** مع كل إصدار توزّعه، وإلا يرفض أندرويد
> التثبيت كتحديث. في CI هذا مضمون تلقائيًا (رقم التشغيل يتزايد).

## 6. مفتاح تشفير القاعدة (تلقائي — لا يُكتب في الكود)

`data/local/DatabaseKeyManager.kt`:
- يولّد عبارة مرور عشوائية **32 بايت** مرة واحدة عند أول تشغيل.
- يخزّنها في `EncryptedSharedPreferences` المختومة بـ `MasterKey` (AES-256-GCM)
  المدعوم بـ Android Keystore.
- لا تُكتب أبدًا كنص صريح، ولا تُضمَّن في المصدر، ولا تغادر الجهاز.

لذلك: لا يوجد «مفتاح قاعدة» تنسخه أو تلصقه — النظام يديره تلقائيًا. ما تحرص عليه هو
**مفتاح التوقيع** (القسم ٢) لأنه ما يُبقي هذا المفتاح التلقائي صالحًا عبر التحديثات.
